# 松鼠世界 · 投递跟踪实施计划

更新日期：2026-09-05。当前阶段：前端页面完成，新增筛选和分页的数据联动待实现。

## 已交付页面与边界

- 主题横幅：复用资料工作台的森林绿、星点、松鼠 Logo 和奶油白标题。
- 求职进度漏斗：七个等高状态卡，数字来自已有投递记录，表示当前状态分布。
- 投递结果表：全宽展示，新增岗位、关键词、地址三个筛选框；长备注可展开查看。
- 分页区：每页 25、50、100 条选择器和上一页、下一页入口。
- 统计模块：转化统计与投递时段观察在桌面端等宽、等高排列，使用原有统计数据。
- 响应式：较窄屏幕将筛选框和统计模块改为单列，桌面左侧导航与手机底部导航保持常驻。

本轮允许填写和重置条件、切换每页条数以检查控件效果，但筛选按钮和翻页按钮禁用；选择条数不会截断真实记录，也不会生成虚假页数。列表明确标注“尚未分页”，筛选区标注“界面预览”。现有投递同步、状态编辑、事件记录和平台证明逻辑继续保留。

## 下一阶段的数据前提

当前 `frontend/src/types.ts` 的 `ApplicationRecord` 有 `job_id`、岗位名称、公司、平台、备注和事件，但没有地址字段。`backend/app/main.py` 的 `GET /api/applications` 当前无查询参数，直接返回全部记录。

后续应先关联岗位数据，补齐城市/区县/原始地址和岗位描述，再设计筛选接口。没有来源的地址应显示“未提供”；不得从公司名称猜测地点，也不得用浏览器当前岗位池替代历史投递资料。历史岗位可能被删除，建议保留投递时岗位快照或使用可空关联并保留来源。

## 筛选与分页约定（待实现）

| 控件 | 计划行为 |
| --- | --- |
| 岗位 | 按岗位名称进行文本匹配，例如“产品经理”“数据分析” |
| 关键词 | 匹配公司、岗位名称、岗位描述、投递备注；具体命中字段可在结果中提示 |
| 地址 | 匹配来源明确的城市、区县和原始地址，例如“上海”“浦东”“张江” |
| 组合条件 | 非空条件之间使用 AND，空条件忽略；去除首尾空格，英文不区分大小写 |
| 每页条数 | 仅允许 25、50、100，默认 25；变更后回到第一页 |
| 翻页 | 使用真实总数计算页数；空结果不显示不存在的第一页，首尾页禁用对应按钮 |

建议在兼容现有调用方的前提下增加分页查询接口或版本化响应，参数包括 `position`、`keyword`、`location`、`page`、`page_size`，返回 `items`、`total`、`page`、`page_size`。不要直接将原有数组接口改成对象而破坏旧客户端。

查询排序固定为投递时间倒序、ID 倒序，保证同一时间记录有确定顺序。所有搜索值使用参数化查询；数据库通配符按约定转义。先过滤完整结果集，再分页，不能只过滤当前页。

## 实施顺序

### A. 补齐数据与接口

1. 检查投递表与岗位表关联，增加历史地点/描述的可靠读取与缺失回退。
2. 增加筛选、计数、稳定排序和服务端分页；校验页码及允许的每页条数。
3. 加入真实记录、空地址、重复时间戳和跨页数据的接口测试。

### B. 接入前端控件

1. 将控件草稿与已应用条件分开，点击“筛选记录”或回车时应用查询；重置恢复全部记录及第一页。
2. 接入加载、无匹配结果、网络失败和重试状态，取消或忽略过期请求，避免快速操作后旧结果覆盖新结果。
3. 接入真实页码、总页数、记录范围和首尾页禁用状态，切换每页条数时保留筛选条件。
4. 状态编辑按记录 ID 保存草稿，提交状态变更后刷新列表，并处理总数变化导致的越界页。
5. 分页就绪后移除“界面预览/尚未分页”提示，启用筛选与翻页按钮。

### C. 统一统计口径

1. 当前统计仍为“全部投递记录”，明确保留这一标签。
2. 后续若与筛选联动，漏斗、转化统计、时段观察必须使用同一组筛选条件，对完整匹配结果聚合，不能只统计当前页。
3. 漏斗的“当前状态数量”与转化率的“历史已读/回复/推进”是不同口径，应分别展示，不能互相代替。
4. 保留既有平台同步的用户确认边界；筛选与翻页不会触发平台投递、模型调用或状态写入。

## 验收清单

- 三种条件分别生效，组合 AND 生效；空格、英文大小写、无匹配、缺失地址、长关键词有明确结果。
- 用超过 100 条测试记录验证 25/50/100 的真实分页：不漏项、不重复、末页正确、空结果与越界页正确。
- 改变条件或条数回到第一页，翻页保留条件；快速连续查询没有旧响应覆盖。
- 筛选后列表、总数与统计口径一致；状态变更后数据与页码正确恢复。
- 键盘能访问全部条件、选择器、备注与翻页按钮；1600/1280/768/390px 下无页面横向溢出。
- 对应测试、后端全量、前端全量、类型检查、生产构建和浏览器验收通过后，按项目规则提交、推送并验证远端提交。
